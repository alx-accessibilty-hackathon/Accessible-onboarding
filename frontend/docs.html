Bridge Onboarding REST API

Welcome to the Bridge Onboarding REST API reference. This API powers both the client-side accessible Web Component (<bridge-onboarding>) and server-to-server integrations for platform partners, employers, and referral NGOs.

Interactive Swagger UI Available

You can execute live requests directly against the API through our Swagger Explorer.

Open Swagger UI ↗

Base URLs

  • Production (via Vercel Proxy): https://accessible-onboarding.vercel.app/api/v1
  • Direct Backend: https://accessible-onboarding.onrender.com/api/v1
  • Local Dev: http://localhost:8080/api/v1
  • Health Check: GET https://accessible-onboarding.vercel.app/health

Authentication & Caller Types

The API enforces role-based security based on caller headers and tokens:

Caller Header / Scheme Used For
Partner Website X-Partner-Key: pk_...
(checked against Origin)		 Public widget configuration, job listings, and registration initialization.
Learner Session Authorization: Bearer lt_...
+ X-Partner-Key		 Saving answers, submitting accommodation requests, submitting registrations.
Staff / Employer Authorization: Bearer st_... Posting jobs, managing candidate applications, reviewing learner referrals.
Partner Server (OAuth) Authorization: Bearer pt_...
(scope: learners:read)		 Server-to-server queries for learners referred to or registered via your organization.

Standard Error Envelope

Every API error returns a uniform JSON response format:

{
  "status": 422,
  "code": "validation_failed",
  "title": "Validation failed",
  "errors": [
    {
      "field": "phone",
      "code": "phone_invalid"
    }
  ]
}

1. Partner Configuration

GET /api/v1/config Requires X-Partner-Key

Fetches the partner's tailored configuration: supported languages, default language, accepted ID routes, referral partners, support phone/telegram, and primary brand theme.

Example Request (cURL):

curl -i -H "X-Partner-Key: pk_demo_savanna" \
  https://accessible-onboarding.vercel.app/api/v1/config

Example Response (200 OK):

{
  "partner": {
    "id": "dbabf95e-ea08-4a6d-a77b-f980b33d8143",
    "name": "Savanna (demo)"
  },
  "languages": ["am", "en"],
  "default_language": "am",
  "id_routes": ["fayda", "kebele_id", "refugee_id", "unhcr_proof", "none"],
  "referral_partners": [
    { "id": "68f0ee77-b364-4299-84cf-87d1a014cf18", "name": "AAAPD" }
  ],
  "help": {
    "phone": "+251 11 000 0000",
    "telegram": "@bridge_help_demo"
  },
  "theme": { "primary": "#cc3636" }
}

2. Job Listings & Details

GET /api/v1/jobs Public

Lists all published, accessible job openings. Supports cursor-based pagination.

Query Parameters:

limitinteger (optional, default 20, max 100)
cursorstring (optional cursor for next page)
curl -i https://accessible-onboarding.vercel.app/api/v1/jobs?limit=10
GET /api/v1/jobs/:id Public

Returns complete details for a single job opening, including accessibility accommodations (e.g. screen reader support, step-free access, flexible hours).

curl -i https://accessible-onboarding.vercel.app/api/v1/jobs/019318b2-32b0-7c22-b5e8-1c4fa42e88a1

3. Learner Registration Flow

POST /api/v1/registrations Requires X-Partner-Key

Initializes a new learner onboarding registration and returns an opaque 30-day learner session token (lt_...).

Request Body:

{
  "flow": "signup",
  "language": "am",
  "simple_mode": false
}

Response (201 Created):

{
  "id": "7fa6b12a-3721-4f90-a7d1-21bbcae41234",
  "token": "lt_98f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5",
  "expires_at": "2026-12-16T12:00:00Z"
}
PUT /api/v1/learner/registrations/:id/answers/:questionId Learner Token Required

Saves or updates an answer for a specific question step (e.g., full_name, phone, dob, id_route). Supports concurrency checks via base_version.

curl -i -X PUT \
  -H "X-Partner-Key: pk_demo_savanna" \
  -H "Authorization: Bearer lt_..." \
  -H "Content-Type: application/json" \
  -d '{"value": "Abebe Kebede", "input_method": "keyboard", "base_version": 0}' \
  https://accessible-onboarding.vercel.app/api/v1/learner/registrations/7fa6b12a-3721.../answers/full_name
PUT /api/v1/learner/registrations/:id/support-request Learner Token Required

Saves the learner's accessibility support needs (screen reader, sign language, flexible hours). Support requests are encrypted in the database via AES-256-GCM.

{
  "needs": ["screen_reader", "extra_time"],
  "other_description": "Need high contrast screen settings",
  "share_with_courses": true,
  "share_with_employers": true
}
POST /api/v1/learner/registrations/:id/submit Learner Token Required

Finalizes and submits the registration. Transitions the registration state from in_progress to submitted and creates the permanent learner profile.

4. Cross-Device Resume & Verification

POST /api/v1/widget/resume/lookup Requires X-Partner-Key

Sends a 6-character keyed hash verification code via SMS to the learner's phone number so they can resume on another phone or browser.

{ "phone": "+251911223344" }
POST /api/v1/widget/resume/verify Requires X-Partner-Key

Verifies the 6-character resume code and returns the active learner session token to resume where the learner left off.

{ "phone": "+251911223344", "code": "H7X9K2" }

5. Partner Server API (OAuth 2.0)

Partners who want to query their referred learners from their own backend server authenticate using standard OAuth 2.0 Client Credentials.

POST /api/v1/oauth/token Server Auth

Exchange your client_id and client_secret for an hourly partner access token (pt_...).

curl -i -X POST \
  -d "grant_type=client_credentials&client_id=savanna-demo&client_secret=...&scope=learners:read" \
  https://accessible-onboarding.vercel.app/api/v1/oauth/token

Response:

{
  "access_token": "pt_3fa85f647c2149b18361092a4e9b72c1",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "learners:read"
}
GET /api/v1/partner-api/learners Bearer pt_... Required

Retrieves all learners referred to or enrolled through your organization, including their validated support requirements and accommodation consents.

curl -i -H "Authorization: Bearer pt_..." \
  https://accessible-onboarding.vercel.app/api/v1/partner-api/learners
