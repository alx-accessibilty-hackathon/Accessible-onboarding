# Backend (Go)

Clean architecture, using the same layout as the G6-WorryMate backend. Gin for HTTP, PostgreSQL (pgx) for data, [sqlc](https://docs.sqlc.dev) to generate the database code, and [goose](https://github.com/pressly/goose)-format migrations.

## Layout

```text
backend/
├── main.go                  wires everything: config → repositories → use cases → controllers → router
├── Config/config.go         every environment variable, read once (nothing else calls os.Getenv)
├── Domain/
│   ├── entities.go          plain structs and shared values (no JSON tags, no database code)
│   └── interfaces.go        use case, repository and service interfaces
├── Usecase/                 business rules and permission checks; depends only on Domain interfaces
├── Repository/              repositories: call sqlc's generated methods, map rows to Domain entities
│   ├── queries/             the SQL you write, one file per table group (input to sqlc)
│   └── sqlc/                generated by sqlc: never edit by hand
├── Infrastructure/          middleware (incl. rate limits) and outside services (security, speech-to-text, SMS)
├── Delivery/
│   ├── Controllers/         HTTP handlers + request/response DTOs (<area>_dto.go)
│   ├── Routers/router.go    every route in one place
│   └── mocks/               generated mocks for tests (mockery)
├── migrations/              goose migrations (also the schema sqlc reads)
└── sqlc.yaml                sqlc settings
```

**Dependency rule:** Controllers → Usecase → Domain ← Repository / Infrastructure. A use case never imports `gin` or `pgx`.

## Conventions

- **IDs are `uuid.UUID`** everywhere: Domain, DTOs and sqlc code.
  - The only string identifiers are the flow file IDs (`"signup"`) and question/step IDs (`"phone"`).
  - Read an ID from the path with `uuidParam(c, "id")`, which answers `400 invalid_id` on a bad value.
- **DTOs live only in `Delivery/Controllers/<area>_dto.go`.** Domain entities have no JSON tags.
  - Each DTO file holds the request structs (with `binding` rules), the response structs, and mapping helpers: `toXDTO(domain)` for responses and `req.toDomain()` for requests.
- **Requests are bound with `bindJSON`, `bindQuery` or `bindForm`** (in `common_dto.go`). They answer for you:
  - **400 `invalid_request`** for unreadable JSON
  - **422 `validation_failed`** with `errors: [{field, code}]`, using JSON field names and codes such as `required`, `too_long` and `invalid_choice`

  A handler starts like this:

  ```go
  var req CreateRegistrationRequest
  if !bindJSON(c, &req) {
      return
  }
  ```

- **Errors:** repositories and use cases return `domain.Err…` sentinels. Controllers never compare error strings.
- **Lists** return `ListResponse[T]` (`items`, `next_cursor`).
- **Config:** add new settings to `Config/config.go` and `.env.example`, then pass the value in from `main.go`.

## Run

```bash
cp .env.example .env          # fill in DATABASE_URL and the keys
go run .                      # http://localhost:8080/health
go test ./...
```

Use Go 1.24. If `go get` tries to download a newer toolchain, run it with `GOTOOLCHAIN=local`.

## Database code with sqlc

sqlc reads the migrations (the schema) and the queries in `Repository/queries/`, then writes type-safe Go into `Repository/sqlc/`. Repositories call that code; nothing else does.

1. **Table change:** add a new migration in `migrations/`, for example `00002_registration.sql`, with `-- +goose Up` and `-- +goose Down` sections. Never edit a merged migration.
2. **Query:** write it in `Repository/queries/<area>.sql` under a name line: `-- name: GetLearner :one` (`:one` returns one row, `:many` a list, `:exec` nothing).
3. **Generate:** run `sqlc generate` from `backend/`. The new method appears on `sqlc.Queries`.
4. **Repository:** call `r.Q.GetLearner(ctx, …)`, turn `pgx.ErrNoRows` into `domain.ErrNotFound`, and map the row to a Domain entity. `partner_repository.go` is the example.
5. **Commit:** commit the generated files too. CI runs `sqlc diff` and fails if they are out of date.

Generated types:
- `uuid` becomes `uuid.UUID`
- `timestamptz` and `date` become `time.Time`
- `jsonb` becomes `json.RawMessage`
- nullable columns become pointers, for example `*string`

**Transactions** (when one action writes several tables):

```go
tx, err := r.DB.Begin(ctx)
defer tx.Rollback(ctx)
q := r.Q.WithTx(tx)
// q.CreateX(...); q.UpdateY(...)
return tx.Commit(ctx)
```

**Install sqlc 1.31.1:**
- **Windows:** download `sqlc_1.31.1_windows_amd64.zip` from https://github.com/sqlc-dev/sqlc/releases/tag/v1.31.1 and put `sqlc.exe` on your PATH.
- **macOS:** `brew install sqlc`.
- **Docker:** `docker run --rm -v "${PWD}:/src" -w /src sqlc/sqlc:1.31.1 generate`.

## Migrations

The files follow goose's format. To apply them to your local database:

```bash
go install github.com/pressly/goose/v3/cmd/goose@latest   # once
goose -dir migrations postgres "$DATABASE_URL" up
```

## Adding an endpoint

1. **Domain:** add the method to the interface in `interfaces.go`, and any new entity to `entities.go`.
2. **Repository:** add the query and call the generated method (see "Database code with sqlc").
3. **Usecase:** implement the rule, including the permission check.
4. **Controller:** bind the DTO, call the use case, return JSON (errors use `ErrorResponse`).
5. **Router:** the route already exists for Must endpoints; it returns 501 until step 4 is done.
6. **Test:** regenerate the mocks and write the use case and controller tests.

   ```bash
   mockery --dir Domain --all --output Delivery/mocks
   ```

7. **Contract:** add the endpoint, with an example, to `../api/openapi.yaml`.
